# אפליקציית בריא.ה — בריף מוצר לפיתוח (ל-Claude Code)

גרסה: מאוחדת · מיועד למסירה ישירה ל-Claude Code כדי להתחיל לבנות.
מסמכי רקע נוספים ומפורטים יותר נמצאים באותה תיקייה (`business-context.md`, `arbox-integration.md`, `vision-and-roadmap.md`, `bria-copilot-context.md`) — המסמך הזה הוא התמצית הבנויה להתחלת עבודה.

## 1. רקע ובעיה

בריא.ה (Briah) היא קהילת וולנס הוליסטית בתל אביב (הירשנברג 14) שמשלבת סדנאות קבוצתיות גוף-נפש, טיפולים אישיים 1:1, וליווי אישי + קהילה, סביב מתודולוגיה של 5 רבדים (קרקוע/פריקה/אינטגרציה/קהילה/משמעות). **הקהילה מעורבת — גברים ונשים כאחד**, ולכן כל טקסט באפליקציה צריך להיות בלשון מכילה (למשל "חבר/ה", לא רק "חברה").

כיום הכל מנוהל בפיזור: ארבוקס (הרשמות/מנויים/לוח זמנים), וואטסאפ (תקשורת), Excel (חיוב מתרגלים, תקציב), וזיכרון אנושי (מעקב אחרי תהליך כל חברה). אין כלי אחד שנותן למלוות ולמטפלים תמונה מרוכזת של כל חברה, שנותן לחברות ליווי בין המפגשים, ושמנהל בצורה מסודרת את החיוב והתשלום למתרגלים.

**המטרה:** אפליקציה אחת שממורכזת סביב האנשים והתהליך (חברות + צוות) — לא עוד כלי הרשמה/תשלום (זה כבר קיים בארבוקס).

## 2. מטרות, בסדר עדיפויות

1. **כלי מעקב למלוות** — תמונה ברורה של מה קורה עם כל חברה, בלי תלות בזיכרון/וואטסאפ.
2. **דיווח וחיוב מתרגלים/מנחים** — מתרגל מדווח חודשית מה העביר, מעלה קבלות, רוני מסמנת אם שולם, ורואה את תנאי ההעסקה של כל אחד/ת. (פירוט מלא בסעיף 7 — **חשוב לרוני, חלק מה-P0**).
3. **ליווי יומי** — נוכחות של בריא.ה בחיי החברה גם בין המפגשים (ציטוט יומי, הודעה למלווה).
4. **מרחב קהילתי** — תוכן ושיתוף בין חברות.
5. **תפעול/הרשמה** — נשען על ארבוקס, לא בונים מחדש.

## 3. Non-Goals (לא בגרסה הראשונה)

| לא בסקופ | למה |
|---|---|
| מערכת הרשמות/תשלומים עצמאית | ארבוקס כבר עושה את זה — קוראים ממנו, לא מחליפים אותו |
| יומן/מערכת שעות עצמאית לסדנאות | נשלף מארבוקס |
| ניתוח שיווקי/תקציבי כללי (לידים, משפך, שימור, תוכן) | **קיים כבר בכלי נפרד ("Bria Copilot") שנבנה ע"י אביב** — לא לבנות פעמיים, ראו `bria-copilot-context.md` |
| מערכת תיעוד קליני מלאה ברמת רשומה רפואית | דורש בדיקה משפטית מראש |
| AI כתחליף לטיפול/אבחון | בעתיד בלבד, ככלי תמיכה ראשונית עם הסלמה מיידית לאדם |

| מלווה | מלווה אישית של קבוצת חברות, כותבת הערות ומשוחחת איתן |

| מנחה סדנה קבוצתית | מעביר/ה שיעורים/סדנאות; זקוק/ה להקשר לפני שנכנס/ת |

## 5. User Stories מרכזיים (לפי פרסונה)

**מלווה:** לראות רק את החברות שלי, עם דגש על מי שכתבה וממתינה לתגובה · לכתוב הערה ולבחור אם היא גלויה לכל הצוות או מוגבלת · לראות סטטוס "כדאי להתעדכן" על מי ששקטה זמן רב.

**מתרגל/ת 1:1:** לכתוב סיכום פגישה מובנה שגלוי רק לניצן · לראות הערות שנכתבו על מטופל/ת בסשן קבוצתי או ע"י המלווה שלו/ה · לסמן פרט כ"קריטי להעברה" · **לדווח בסוף/במהלך החודש אילו טיפולים/סדנאות העברתי, לצרף קבלות, ולראות את סטטוס התשלום שלי** · **לראות את תנאי ההעסקה שלי (תעריף, תנאי תשלום) — קריאה בלבד**.

**מנחה סדנה קבוצתית:** לראות לפני הסדנה מי מגיעה, מי חדשה, בקשות מיוחדות · לראות רק מה שסומן קריטי או שותף איתי במפורש.

**ניצן:** לראות את כל מה שקורה בצוות ועם המטופלות — התמונה הטיפולית המלאה.

**רוני:** לראות גם את הצד התפעולי-פיננסי לצד מה שניצן רואה · **להזין/לערוך את תנאי ההעסקה של כל מתרגל/ת (תעריף, סוג הסכם, תנאי תשלום) · לעבור על דיווחי מתרגלים ולסמן שולם/לא שולם/שולם חלקית · להעלות ולשמור מסמכים כלליים (חוזים, ביטוחים וכו') במקום אחד**.

## 7. פירוט: דיווח, תנאי העסקה, ותשלום מתרגלים

זה פיצ'ר מוגדר במלואו, מחליף תהליך ידני שקיים היום ב-Excel:

1. **תנאי העסקה (PractitionerAgreement)** — רוני מזינה לכל מתרגל/ת: סוג הסכם (לפי טיפול/סדנה, ריטיינר, אחוז מהכנסה וכו'), סכום/תעריף, תנאי תשלום, תאריך התחלה (וסיום אם רלוונטי). רק רוני עורכת; המתרגל/ת רואה את שלו/ה בלבד, בקריאה בלבד; אף אחד אחר לא רואה תנאי העסקה של אף אחד.
2. **דיווח חודשי (PractitionerSubmission)** — המתרגל/ת נכנס/ת ומזין/ה רשימת טיפולים/סדנאות שהעביר/ה באותו חודש (תאריך, סוג, הערה חופשית), ומצרף/ת קבלות (או כל קובץ רלוונטי).
3. הדיווח מגיע כ"דוח" לרוני.
4. רוני מסמנת סטטוס תשלום מול הדיווח: שולם / לא שולם / שולם חלקית, יכולה להוסיף הערה.
5. המתרגל/ת רואה בכל רגע את סטטוס התשלום של הדיווחים שלו/ה.

## 8. מטריצת הרשאות

| תפקיד | רואה | כותב/עורך |
|---|---|---|
| רוני | הכל, כולל פיננסים ותנאי העסקה של כולם | תנאי העסקה, סימון תשלום, מסמכים כלליים |
| ניצן | הכל מלבד תנאי העסקה/תשלומים (אלא אם רוני משתפת) | — |
| מלווה | החברות שלה בלבד | הערות + הודעות לחברות |
| מתרגל/ת 1:1 | הערות קבוצתיות/מלווה על מטופליו · תנאי ההעסקה **שלו/ה בלבד** · הדיווחים **שלו/ה בלבד** | סיכום פגישה (לניצן בלבד) · דיווח חודשי + קבלות (רק שלו/ה) |
| מנחה סדנה קבוצתית | הערות מסומנות "קריטי" + הערות ששותפו במפורש | — |

כל הערה של מלווה/מתרגל 1:1 נושאת טוגל שהכותב/ת בוחר/ת: צוות מלא או מוגבל (מלווה/ניצן/רוני).

## 9. מודל נתונים — תוספות מרכזיות לדיווח/תשלום

```
PractitionerAgreement (תנאי העסקה)
- practitioner_id, סוג הסכם, תעריף/סכום, תנאי תשלום, תאריך התחלה/סיום, הערות
- רק Owner עורך; המתרגל/ת רואה את שלו/ה בלבד, קריאה בלבד

PractitionerSubmission (דיווח חודשי)
- id, practitioner_id, חודש/שנה
- items[]: תאריך, סוג טיפול/סדנה, הערה
- receipts[]: קבצים מצורפים
- payment_status: לא שולם | שולם חלקית | שולם
- marked_by (Owner), marked_at, הערת רוני

Document (מסמך כללי — "להעלות שם הכל")
- id, קובץ, שם/תיאור, הועלה ע"י, תאריך
- linked_to: chevra_id | practitioner_id | none (מסמך כללי לא-משויך, למשל חוזה שכירות/ביטוח)
- visibility: Owner בלבד כברירת מחדל, ניתן להרחיב
```

לשאר הישויות (Chevra, Cycle, Session, Note, MatargelSummary, PersonalPlan, ConsentForm) — ראו `data-model.md` בתיקייה.

## 10. אינטגרציית ארבוקס — תמצית (פירוט מלא ב-`arbox-integration.md`)

- יש API רשמי: REST, Base URL `https://arboxserver.arboxapp.com/api/public/v3/`, אימות ב-API Key.
- קטגוריות רלוונטיות: Leads, Membership Types, Users, Schedule, Reports (כולל ככל הנראה גם הכנסות/הוצאות — לאמת).
- מיקום יחיד רשום בארבוקס: הירשנברג 14 (מזא"ה 9 הוא רק מרחב מושכר לאירועים, לא location בארבוקס).
- לפני build: רוני צריכה להנפיק API key מהגדרות החשבון בארבוקס ולמסור אותו ישירות לסביבת הפיתוח (לא בצ'אט).
