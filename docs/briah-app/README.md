# בריא.ה — קבצי בריף לאפליקציה

התיקייה הזו מרכזת את כל מה שצריך כדי לבנות את אפליקציית בריא.ה (חברות/מלוות/צוות), כך שלא צריך לשחזר את הבריינסטורם מחדש בכל שיחה.

## למסירה ישירה ל-Claude Code

**[`dev-brief.md`](./dev-brief.md)** — המסמך המאוחד והמעודכן ביותר. מכיל הכל: רקע, מטרות, פרסונות, user stories, דרישות P0/P1/P2, מטריצת הרשאות, מודל נתונים, אינטגרציית ארבוקס, ושאלות פתוחות. **זה הקובץ שמתחילים ממנו.**

## סדר קריאה מומלץ (לרקע מפורט)

1. [`PRD.md`](./PRD.md) — תמצית המוצר: למה בונים, למי, סדר עדיפויות, שלבי בנייה מוצעים.
2. [`business-context.md`](./business-context.md) — רקע עסקי/מתודולוגי: 5 הרבדים, מסלולי מנוי ומחירים, מסע לקוח, מחזורים, צוות, טון כתיבה.
3. [`permissions-model.md`](./permissions-model.md) — מי רואה מה. הכי מפותח ומוכן לבנייה.
4. [`data-model.md`](./data-model.md) — טיוטת ישויות ונתונים.
5. [`user-flows.md`](./user-flows.md) — תרחישי שימוש מרכזיים לפי תפקיד.
6. [`vision-and-roadmap.md`](./vision-and-roadmap.md) — החזון המלא, מפורק למודולים ולסדר בנייה.
7. [`arbox-integration.md`](./arbox-integration.md) — פרטי ה-API הרשמי של ארבוקס.
8. [`bria-copilot-context.md`](./bria-copilot-context.md) — כלי נפרד ("Bria Copilot") שאביב בונה לאנליטיקה/תקציב/שיווק — לא לבנות פעמיים.

## מצב נוכחי (עדכון אחרון)

התחלנו בבנייה בפועל של **שלב 1 / מודול 1 (חברות/מלוות)** בתיקייה `member-app/` בשורש הריפו. ראו `member-app/README.md` להתקדמות, החלטות ארכיטקטורה, ומה עדיין דורש קלט מרוני (מפתחות API, החלטות עקרוניות).
